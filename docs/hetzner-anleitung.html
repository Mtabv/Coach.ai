Coach.AI auf deinen Hetzner-Server

Schritt für Schritt, ohne Vorkenntnisse. Du arbeitest die Schritte der Reihe nach ab und hakst sie ab. Befehle kopierst du mit „Kopieren“ und fügst sie ein.

Worum es geht

Am Ende läuft Coach.AI unter einer eigenen Adresse, etwa https://coach.deine-domain.de, mit Login für dich und deinen Co-Trainer. Die Daten liegen auf deinem Server, nicht bei Dritten. Dafür richten wir vier Dinge ein:

SchlüsselDein Laptop bekommt einen digitalen Schlüssel für den Server, statt eines Passworts.
ServerUpdates, Firewall und Backups, damit er sicher läuft.
AdresseEine Subdomain zeigt auf den Server, mit verschlüsselter Verbindung (HTTPS).
AutomatikNeue Versionen kommen von GitHub automatisch auf den Server.
Wichtig: Passwörter und Schlüssel schickst du nie in den Chat, auch mir nicht. Wo ein Geheimnis gebraucht wird, legst du es selbst auf dem Server oder in GitHub ab. Ich arbeite nur mit dem Code im Repository.

Teil A: Laptop und Server vorbereiten

einmalig, etwa 45 bis 60 Minuten

1

Herausfinden, was für ein Server es ist

  1. Bei Hetzner einloggen. Liegt der Server unter console.hetzner.cloud, ist es ein Cloud-Server, und diese Anleitung passt genau. Liegt er unter robot.hetzner.com, ist es ein dedizierter Server, die Schritte sind fast gleich; sag mir dann kurz Bescheid.
  2. Notiere dir die IPv4-Adresse des Servers (vier Zahlen mit Punkten, zum Beispiel 203.0.113.10) und das Betriebssystem. Am besten ist Ubuntu 24.04.
  3. Läuft auf dem Server schon etwas, zum Beispiel eine Webseite? Dann bitte nichts löschen und mir vorher sagen, was dort läuft.
2

Schlüssel auf dem Laptop erzeugen

Ein SSH-Schlüssel besteht aus zwei Dateien: einer öffentlichen (endet auf .pub, darf auf den Server) und einer privaten (bleibt immer auf deinem Laptop, niemals weitergeben).

Startmenü öffnen, PowerShell eintippen und öffnen. Dann:

Spotlight (Cmd + Leertaste), Terminal eintippen und öffnen. Dann:

ssh-keygen -t ed25519 -C "laptop-manuel"
  • Bei der Frage nach dem Speicherort einfach Enter drücken.
  • Dann eine Passphrase wählen, also ein Passwort für den Schlüssel. Beim Tippen siehst du nichts, das ist normal. Gut merken.

Den öffentlichen Schlüssel anzeigen und komplett kopieren (eine lange Zeile, beginnt mit ssh-ed25519):

Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
cat ~/.ssh/id_ed25519.pub
3

Schlüssel beim Server hinterlegen

Fall 1: Der Server ist neu oder wird neu angelegt. In der Hetzner Cloud Console im Projekt unter Sicherheit → SSH-Keys auf „SSH-Key hinzufügen“, die kopierte Zeile einfügen, Namen vergeben. Beim Erstellen des Servers diesen Schlüssel auswählen.

Fall 2: Der Server läuft schon. Den Server anklicken, oben auf das Symbol Konsole (>_). Es öffnet sich ein schwarzes Fenster im Browser. Als root mit dem Root-Passwort einloggen; das stand in der Hetzner-E-Mail, sonst unter „Rescue → Root-Passwort zurücksetzen“ ein neues setzen. Dann:

mkdir -p ~/.ssh && nano ~/.ssh/authorized_keys
  • Die kopierte Zeile einfügen. Im Browser-Fenster geht Einfügen oft nur über das Menü oder mit Strg + Umschalt + V.
  • Speichern mit Strg + O, dann Enter, schließen mit Strg + X.
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
4

Zum ersten Mal vom Laptop verbinden

Zurück in PowerShell oder Terminal auf dem Laptop. Statt 203.0.113.10 deine Server-Adresse einsetzen:

ssh root@203.0.113.10
  • Beim ersten Mal kommt eine Frage nach einem „fingerprint“. Mit yes bestätigen.
  • Dann die Passphrase deines Schlüssels eingeben.
  • Steht vorne jetzt etwas wie root@…:~#, bist du auf dem Server. Mit exit kommst du zurück.
Ab hier tippst du alle Befehle in diesem Fenster, also auf dem Server, solange nichts anderes dabeisteht.
5

Server auf den neuesten Stand bringen

apt update && apt upgrade -y

Sicherheitsupdates künftig automatisch einspielen lassen. Bei der Frage „Yes“ wählen:

apt install -y unattended-upgrades && dpkg-reconfigure -plow unattended-upgrades
6

Firewall und Backups bei Hetzner einschalten

  1. In der Cloud Console unter Firewalls eine neue Firewall anlegen. Eingehend nur erlauben: TCP 22 (SSH), TCP 80 und TCP 443 (Webseite). Die Firewall dem Server zuweisen.
  2. Beim Server unter Backups die automatischen Backups einschalten. Das kostet 20 % des Serverpreises und rettet im Ernstfall alles.
7

Login per Passwort abschalten

Erst machen, wenn Schritt 4 sicher funktioniert. Lass das Fenster offen und teste danach in einem zweiten Fenster, ob ssh root@… noch geht. Sonst sperrst du dich aus. Notfalls hilft dann immer noch die Hetzner-Konsole aus Schritt 3.
echo "PasswordAuthentication no" > /etc/ssh/sshd_config.d/00-coachai.conf && systemctl restart ssh
8

Docker installieren

Docker packt Coach.AI, die Datenbank und den Datendienst in fertige Pakete. So musst du nichts einzeln installieren.

curl -fsSL https://get.docker.com | sh

Test: Steht am Ende „Hello from Docker!“, passt alles.

docker run --rm hello-world
9

Adresse einrichten

  1. Klären, welche Domain du nutzt. Entweder eine Subdomain der Vereinsseite, etwa coach.tsg-wilhelmshoehe.de (dafür braucht es den, der die Vereinsdomain verwaltet), oder eine eigene Domain, die es ab etwa einem Euro im Monat gibt, zum Beispiel direkt bei Hetzner.
  2. Bei der Domain-Verwaltung einen A-Eintrag anlegen: Name coach, Wert ist die IPv4-Adresse des Servers.
  3. Nach einigen Minuten bis Stunden prüfen, auf dem Laptop:
ping coach.deine-domain.de

Erscheint die Server-Adresse in der Antwort, stimmt es. Mit Strg + C beenden.

Teil B: Coach.AI aufspielen

sobald die Server-Fassung fertig ist, etwa 15 Minuten

10

Coach.AI herunterladen und starten

Ich lege dafür im Repository einen Ordner deploy an. Darin steckt alles: Coach.AI, die Datenbank, der Datendienst und ein Webserver, der das HTTPS-Zertifikat selbst besorgt. Auf dem Server:

git clone https://github.com/mtabv/coach.ai.git /opt/coachai && cd /opt/coachai/deploy && cp .env.beispiel .env

Die Einstellungen öffnen und die Domain eintragen. Passwörter erzeugst du direkt auf dem Server, nie im Chat:

openssl rand -hex 24
nano .env

Starten:

docker compose up -d

Nach ein bis zwei Minuten ist Coach.AI unter deiner Adresse erreichbar. Beim ersten Aufruf legst du dein Trainer-Konto an und lädst deinen Co-Trainer ein.

Ist das Repository auf GitHub privat, klappt das Herunterladen so nicht. Sag mir dann Bescheid, ich ergänze einen Lesezugang nur für den Server.

Teil C: Neue Versionen automatisch, „über hier“

einmalig, etwa 20 Minuten

11

Einen eigenen Zugang nur für GitHub anlegen

So funktioniert es: Ich ändere Coach.AI hier im Chat und lege die Änderung im Repository ab. Sobald du sie auf GitHub freigibst, spielt GitHub sie selbst auf deinen Server. Dafür bekommt GitHub einen eigenen Schlüssel, der nur das darf. Ich sehe diesen Schlüssel nie.

Auf dem Server: einen Benutzer deploy anlegen, der Coach.AI aktualisieren darf:

adduser --disabled-password --gecos "" deploy && usermod -aG docker deploy && mkdir -p /home/deploy/.ssh && chown -R deploy:deploy /home/deploy/.ssh /opt/coachai

Auf dem Laptop (neues PowerShell- oder Terminal-Fenster) einen zweiten Schlüssel nur für GitHub erzeugen. Bei der Passphrase zweimal nur Enter drücken:

ssh-keygen -t ed25519 -f coachai-deploy -C "github-deploy"

Es entstehen zwei Dateien im aktuellen Ordner: coachai-deploy.pub (öffentlich) und coachai-deploy (privat).

  1. Den Inhalt von coachai-deploy.pub auf dem Server in /home/deploy/.ssh/authorized_keys einfügen (wie in Schritt 3, mit nano).
  2. In GitHub das Repository mtabv/coach.ai öffnen → Settings → Secrets and variables → Actions → New repository secret. Drei Einträge anlegen:
    NameInhalt
    DEPLOY_HOSTdie IPv4-Adresse des Servers
    DEPLOY_USERdeploy
    DEPLOY_SSH_KEYder komplette Inhalt der Datei coachai-deploy, also der privaten, mit allen Zeilen
  3. Die Datei coachai-deploy danach vom Laptop löschen. Sie liegt jetzt sicher bei GitHub.
Ab dann gilt: Ich baue, du gibst frei, GitHub spielt auf. Du musst dich für Updates nicht mehr auf dem Server einloggen.

Wenn etwas hakt

MeldungBedeutung und Lösung
Permission denied (publickey)Der Server kennt deinen Schlüssel nicht. Schritt 3 prüfen: ganze Zeile eingefügt, ohne Zeilenumbruch?
Connection timed outFalsche Adresse oder die Firewall lässt Port 22 nicht durch. IP-Adresse und Schritt 6 prüfen.
REMOTE HOST IDENTIFICATION HAS CHANGEDKommt, wenn der Server neu installiert wurde. Auf dem Laptop ssh-keygen -R 203.0.113.10 mit deiner Adresse ausführen und neu verbinden.
Seite lädt nichtZeigt ping aus Schritt 9 die richtige Adresse? Sind Port 80 und 443 in der Firewall offen?

Kommst du nicht weiter, schick mir die Fehlermeldung als Text. Nur die Meldung, keine Passwörter und keine Schlüssel.

Kleines Wörterbuch

Terminal, PowerShell
Ein Fenster, in dem man Befehle tippt statt zu klicken.
SSH
Sichere Verbindung vom Laptop zum Server.
Schlüssel
Ersatz für ein Passwort. Der öffentliche Teil liegt auf dem Server, der private bleibt bei dir.
root
Der Hauptbenutzer des Servers, er darf alles.
Docker
Fertige Programmpakete, die auf jedem Server gleich laufen.
DNS, A-Eintrag
Das Telefonbuch des Internets: Es übersetzt die Adresse in die Server-IP.
HTTPS
Verschlüsselte Verbindung, erkennbar am Schloss im Browser.
Secret (GitHub)
Ein geschützter Eintrag, den nur die Automatik lesen kann, niemand sonst.
